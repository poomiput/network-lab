4. Routing Policy

  • OSPF 10 area 0 ภายใน HQ: router-id = Loopback0 · passive-interface default · เปิดเฉพาะลิงก์ CE–MLS · SVI / Loopback อยู่ใน area 0 (passive) · neighbor FULL ครบ 4 คู่
  • iBGP CE01 ↔ CE02 (AS65106) ผ่าน Loopback0 + next-hop-self = Established
  • Default route: CE01 ส่งเข้า OSPF metric 1 (หลัก) · CE02 metric 50 (สำรอง) — ตอนนี้ default มาจาก ISP จำลอง
  • eBGP ออกแบบตามใบงาน (สคริปต์ U3 พร้อมวาง): รับแค่ 0.0.0.0/0 (prefix-list DEFAULT-ONLY + local-pref 200/100) · ส่งแค่ 198.51.100.0/28 (OWN-PUBLIC) · maximum-prefix 1 · route Null0 สำหรับ /28 → ไม่ประกาศ Private และไม่ทำ Transit
  • Branch: 10.6.16.0/20 → Tunnel1 (หลัก) / Tunnel2 AD 20 · HQ redistribute static ของสาขา metric 20 (CE01) / 100 (CE02) — รอ ISP

13. Known Issues

  • ไม่มี ISP G01/G02 จริง → WAN ทั้ง 3 จุดจำลองด้วย Loopback101 (IP ตามทะเบียน + 192.0.2.10 เป็นอินเทอร์เน็ต) · eBGP / Exact Prefix Filter / GRE T1–T2 / Private Route สาขา ผ่านแค่ใน EVE-NG · สคริปต์ U3–U5 พร้อมวาง · ต้องรัน SIM-OFF ก่อนต่อ ISP จริง
  • NAT (Step 07B): config ลงแล้ว แต่ IOS-XE ทิ้งแพ็กเก็ตที่ route เข้า Loopback ก่อนถึง NAT จึงพิสูจน์การแปลงได้เมื่อมี WAN จริงเท่านั้น
  • C9200L ไม่มี HSRP → ใช้ VRRPv3 (ชุด HSRP สำหรับ C9300 เก็บไว้และผ่าน Rack 7 ต.ค.)
  • Collector / NTP อยู่บน Server DMZ ชั่วคราวแทน G04 (ในระบบจริงไม่ควรวางงานภายในใน DMZ)
  • Hostname บนเครื่อง ยังเป็นชื่อสั้น (CE01 …) ส่วนผังใช้ชื่อตามใบงาน (G06-HQ-CE01 …)
  • Branch Single WAN เป็นจุดเดียวตามใบงาน: WAN ขาด → ไม่มีทางออก แต่บริการในสาขาใช้ได้ (ทดสอบแล้ว)
  • ตัวอย่างใบงานขัดกันเอง: DMZ 10.6.5.0/24 vs 198.51.100.8/29 (เลือก /29) · Branch LAN /24 vs /20 (เลือก /20 ตามทะเบียน)

15. Packet Flow + Design Decision (เตรียมตอบรายบุคคล)

ATM → Transaction App (10.6.2.100 → 10.6.1.10 TCP 8443)

  1. ATM ปลายทางคนละวง → ส่งไป Gateway 10.6.2.1 (VIP VRRP 30 = MLS01 MASTER) · ARP ได้ MAC เสมือน 0000.5e00.011e
  2. MLS01 รับเข้า Vlan30 → ตรวจ ATM-IN ขาเข้า: บรรทัด 40 permit tcp → host 10.6.1.10 eq 8443 ✅
  3. Route ภายใน MLS (connected Vlan20) → ส่งออก Gi1/0/6 → App ตอบกลับ
  4. Return Path: App → GW 10.6.1.1 (MLS01) → Vlan30 → ATM · ขาออก Vlan30 ไม่มี ACL จึงไม่ถูกตัด · ไม่มี NAT (ภายในองค์กร)
  5. ถ้า ATM ขอ 8080 / Teller / Admin / DB → ตกบรรทัด 50–90 → MLS ตอบ ICMP unreachable + log

DNS Request แยกจาก Application Flow

Client ถามชื่อก่อน: UDP/TCP 53 ไป 192.0.2.10 (ATM-IN บรรทัด 10/20 อนุญาตเฉพาะ DNS) → ได้ IP แล้วจึงเปิด Flow บริการจริงแยกอีกเส้น · DNS ตอบได้ ≠ บริการใช้ได้ ต้องตรวจทั้งสองทาง (ตอนนี้ DNS จริงอยู่ที่ G01/G03 ซึ่งยังไม่มี)

Teller → Internet / Partner (เมื่อมี ISP)

Teller → MLS01 → default O*E2 จาก CE01 (metric 1) → CE01 eBGP default (LP 200) → G01 · ที่ CE01 ทำ PAT ด้วย Loopback1 198.51.100.1 (NAT-ELIGIBLE: ไม่ NAT เมื่อปลายทางเป็น 10.6.0.0/16) · Return กลับเข้า CE01 ตัวเดิมเพราะ Public /28 ประกาศจาก CE01 · G01 ขาด → default ย้ายไป CE02 (ทดสอบแบบจำลองแล้ว 40/40) — Connection เดิมที่ผ่าน NAT ของ CE01 อาจหลุด ต้องเปิดใหม่

HQ ↔ Branch (เมื่อมี ISP)

HQ → CE01 (static 10.6.16.0/20 → Tunnel1, redistribute เข้า OSPF metric 20) → GRE ห่อด้วย 198.51.100.1 → 198.51.100.161 ผ่าน WAN → R01 · Tunnel1 ล่ม → CE02/Tunnel2 (metric 100) · Branch WAN ขาด = ทุก Tunnel ขาด (Single WAN)

Design Decision

  • VRRPv3 แทน HSRP เพราะ C9200L ไม่รองรับ HSRP · priority 110/100 + preempt ให้ MLS01 เป็นหลักทุก VLAN
  • DMZ 198.51.100.8/29 (Public) แยกจาก Private · Server DMZ ไม่ต้อง NAT · Database รับเฉพาะ App
  • ACL ขาเข้า SVI ของ ATM (กรองใกล้ต้นทาง) + ACL ขาออก Vlan40 ปกป้อง Database จากทุกวง
  • เพิ่มบรรทัด DHCP / VRRP / ICMP ใน ATM-IN เพราะ deny any ท้าย ACL จะตัด control-plane ที่ Gateway ต้องใช้
  • Default จาก CE01 metric 1 / CE02 metric 50 + local-pref 200/100 ใน BGP → ทางหลัก/สำรองชัดเจนทั้ง OSPF และ BGP
